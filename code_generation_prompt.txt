# SECTION 1 - ORIGINAL ASSIGNMENT (verbatim)
==================================================================

Write a C or C++ program that reads a line of text and extracts a single valid IPv4 address, optionally followed by a port number, embedded anywhere in that text. Only digits, periods (.), and colons (:) are ever part of a valid token; every other character is garbage and is skipped. A candidate token must match the address grammar in full: no partial matches, no truncating to find a valid piece inside a longer run.

An address is four octets separated by periods (octet.octet.octet.octet), each octet 1-3 digits, value 0-255, no leading zero unless the value is exactly 0. An optional :port may follow the fourth octet: 1-5 digits, value 0-65535, same leading-zero rule. If a colon is present, the port must be fully valid or the entire match, address included, is rejected.

Function prototype
The function returns whether a valid address was found, and delivers the address and port through two additional parameters.
C:
// Returns 1 if a valid address was found, 0 otherwise.
// On success: *outAddress holds the 32-bit value, and
// *outPort holds the port number, or -1 if no port was present.
// On failure: *outAddress is set to 0 and *outPort is set to -1.
int extractIPv4(const char* str, unsigned long* outAddress, int* outPort);
C++
// Returns true if a valid address was found, false otherwise.
// On success: outAddress holds the 32-bit value,
// and outPort holds the port number, or -1 if no port was present.
// On failure: outAddress is set to 0 and outPort is set to -1.
bool extractIPv4(const std::string& str, unsigned long& outAddress, int& outPort);

Built-in functions/libraries you may not use
* Any string-to-number conversion function: atoi, atol, atoll, strtol, strtoul, strtod, stoi, stol, stoul, sscanf, scanf with numeric conversions.
* Any address-parsing library function: inet_aton, inet_pton, inet_addr, or equivalents.
* Any regular-expression facility (std::regex, POSIX regex.h, or similar). The parsing and validation logic must be my own character-by-character code, not a pattern matched by a library.
* Standard character-classification functions (isdigit, etc.) are fine to use.

Other requirements
* Exactly one valid address may be extracted per input line; everything else in the line is either garbage (skipped) or part of a candidate token that fails validation.
* Reject anything that does not exactly match the grammar above: wrong octet count, empty octet, out-of-range octet or port, a disallowed leading zero, a second colon, a colon not immediately after the fourth octet, or a stray period/colon directly adjacent to an otherwise-valid address.
* On success, print: "Extracted IPv4 address: A.B.C.D (decimal value: N, port: P) " where N is the 32-bit decimal value and P is the port number or the literal text none.

Program requirements
* Input loop: main continuously prompts the user for input until the user enters END (case-sensitive), then prints "Program terminated." and exits.
* Extraction function: implement extractIPv4 exactly as prototyped above. All digit accumulation must be done by hand.
* Display: main receives the result from extractIPv4 and formats the output exactly as specified above.

# SECTION 2 - BINDING DECISIONS (ASSUMPTIONS)

## Language and build
A1. Use C++ (not C), with the C++ prototype exactly as written: `bool extractIPv4(const std::string& str, unsigned long& outAddress, int& outPort);`. Do not rename the function or change its parameter types, parameter names, or return type.
A2. Target standard C++17. The file must compile with zero warnings using:
    g++ -std=c++17 -Wall -Wextra -pedantic -o ipv4 ipv4_extractor.cpp
A3. Only these headers are allowed: <iostream>, <string>, <cctype>. Do not include <regex>, <sstream>, <cstdlib>, <cstdio>, <charconv>, <arpa/inet.h>, or anything else.
A4. Everything lives in one file named ipv4_extractor.cpp. No global variables, no static local state, no classes.

## Tokenizing
A5. Token characters are exactly: '0' through '9', '.', and ':'. Every other character is garbage. That includes letters, spaces, tabs, punctuation such as - _ , ; / \ ( ) [ ] { } @ = # " ' and any non-ASCII byte.
A6. A garbage character acts as a DELIMITER. It splits the text into separate tokens. It is NOT deleted, and the pieces on either side are NEVER glued back together. Example: "192.168.1x.5" contains two tokens, "192.168.1" and ".5", and both are invalid.
A7. A candidate token is a MAXIMAL run of consecutive token characters. Always extend the run over every adjacent token character on both sides. Never begin a match in the middle of a run, and never stop before the run ends.
A8. Each candidate token is validated as a whole against the grammar. It is entirely valid or entirely discarded. Never look for a valid substring inside an invalid token. Example: "1.2.3.4.5" is rejected; it is not "1.2.3.4" followed by leftovers.
A9. Scan left to right. The first token that validates is the answer. Stop immediately and do not examine later tokens. A token that fails validation does not stop the scan; move on to the next token. (The assignment says a line contains at most one valid address. Leftmost-wins is my deterministic tie-break if there are two.)

## Grammar
A10. Full grammar of one token: octet '.' octet '.' octet '.' octet [ ':' port ]
A11. Octet rules:
     - 1 to 3 decimal digits (a 4th digit means reject, even "0000").
     - Value 0 to 255.
     - If it has more than one digit, its first digit must not be '0'. So "0" is valid, while "00", "000", "01", "007" are invalid.
A12. Port rules:
     - 1 to 5 decimal digits (a 6th digit means reject, even "000000").
     - Value 0 to 65535. Port 0 is valid.
     - If it has more than one digit, its first digit must not be '0'. So "0" is valid, while "00", "080", "0080", "00000" are invalid.
A13. Exactly three periods, each strictly between two octets. A leading period, trailing period, doubled period, or a period after the 4th octet means reject.
A14. A colon is legal only immediately after the last digit of the 4th octet, and only once, and it must be followed by at least one port digit. An empty port ("1.2.3.4:"), a second colon, a leading colon, or a colon anywhere else in the token means reject.
A15. Nothing may follow the port (or the 4th octet, if there is no port) inside the same token. "1.2.3.4:80." is rejected.
A16. No fallback. If a colon is present and the port is invalid, the WHOLE token is rejected. Do NOT return the address with "no port". Example: "1.2.3.4:99999" is rejected.

## Numbers
A17. Digits are accumulated by hand with `value = value * 10 + (digit - '0')`, using an `unsigned long` accumulator. The digit-count limit is checked BEFORE each digit is accumulated, so overflow is impossible and very long digit runs fail fast. No conversion function from any library, including stringstream >>, std::from_chars, and std::stoull.
A18. The 32-bit value is (octet1 << 24) | (octet2 << 16) | (octet3 << 8) | octet4, where the first octet written is the most significant byte. Compute it in `unsigned long`, never in `int`, so no sign problems occur. The result is always between 0 and 4294967295.
A19. Port is stored in the `int` outPort. The value -1 means "no port". Port 0 is a real port and is not "none".
A20. Success is decided ONLY by extractIPv4's return value. "0.0.0.0" succeeds with address 0. main must never infer failure from address == 0 or port == -1.

## Function contract
A21. The very first thing extractIPv4 does is set outAddress = 0 and outPort = -1. It writes the real values only after a token has been fully validated (use local temporaries so a half-parsed token can never leak into the outputs). On failure the outputs remain 0 and -1.
A22. extractIPv4 never prints, never reads input, and has no side effects other than the two output parameters.
A23. `char` may be signed. Any call to isdigit must be `std::isdigit(static_cast<unsigned char>(c))`.

## main and I/O
A24. Read each line with std::getline(std::cin, line), so lines of any length work.
A25. After reading, remove exactly one trailing '\r' if present (Windows line endings). Do no other trimming.
A26. Quit check: the line is exactly "END" after A25. Case-sensitive. These do NOT quit and are treated as ordinary input: "end", "End", "END " (trailing space), " END", "END 1.2.3.4".
A27. If getline fails (end of input / Ctrl-D) without END being seen, leave the loop and behave exactly as if END had been entered, printing the termination message. No infinite loop.
A28. Before every read, print this prompt with no newline and flush it: `Enter a line of text (or END to quit): `
A29. Success output, exactly, followed by a single newline:
     Extracted IPv4 address: A.B.C.D (decimal value: N, port: P)
     - There is NO trailing space. (The trailing space in the assignment text is treated as a formatting artifact.)
     - A.B.C.D is rebuilt inside main from the 32-bit value: A = (addr >> 24) & 0xFF, B = (addr >> 16) & 0xFF, C = (addr >> 8) & 0xFF, D = addr & 0xFF. main only receives the combined value and the port.
     - N is the unsigned decimal value.
     - P is the port in decimal, or the lowercase literal text none when outPort == -1.
A30. Failure output (unspecified by the assignment; this is my choice), followed by a newline: `No valid IPv4 address found.`
A31. An empty line or whitespace-only line is NOT a quit; it goes through extraction and prints the failure message.
A32. On quit or EOF print `Program terminated.` followed by a newline, then return 0 from main.

Order of the file, top to bottom:

2. The three #include lines.
3. Named constants (no magic numbers anywhere in the logic):

Style rules:

- No `auto`, no lambdas, no goto, no clever one-liners, no ternary chains. Write it the plain, obvious way, because a beginner has to read it.
- Braces on every if/while/for, even one-line bodies. 4-space indentation. Lines up to about 100 characters.
- Use std::size_t for string positions.

Exactly these helper functions (in the anonymous namespace):

1. `bool isDigitChar(char c)` - true if c is '0' to '9', using isdigit with the cast from A23.

2. `bool isTokenChar(char c)` - true if c is a digit, '.', or ':'.

3. `bool readNumberField(const std::string& s, std::size_t& pos, std::size_t end, int maxDigits, unsigned long maxValue, unsigned long& outValue)`
   Reads ONE number (an octet or a port) starting at pos, never reading at or past `end`. `pos` is a reference so the caller's position moves forward past the digits. Exact steps:
   a. digitStart = pos; count = 0; value = 0.
   b. While pos < end and s[pos] is a digit:
        - if count == maxDigits, return false (this would be one digit too many)
        - value = value * 10 + (s[pos] - '0'); count++; pos++.
   c. If count == 0, return false (empty field).
   d. If count > 1 and s[digitStart] == '0', return false (leading zero).
   e. If value > maxValue, return false.
   f. outValue = value; return true.
   This one function serves both octets (3 digits, max 255) and ports (5 digits, max 65535).

4. `bool parseCandidate(const std::string& s, std::size_t start, std::size_t end, unsigned long& outAddress, int& outPort)`
   Validates the single token s[start .. end), where `end` is one past the last character. Exact steps:
   a. pos = start; address = 0 (local variable).
   b. Loop i from 0 to NUM_OCTETS - 1:
        - call readNumberField for an octet; if it returns false, return false.
        - address = (address << 8) | octetValue.
        - if i < NUM_OCTETS - 1: require pos < end and s[pos] == '.', otherwise return false; then pos++.
   c. port = NO_PORT.
   d. If pos < end:
        - require s[pos] == ':', otherwise return false (this catches a stray '.' after the 4th octet).
        - pos++.
        - call readNumberField for a port; if false, return false (this catches an empty port, a bad port, or a leading zero).
        - port = static_cast<int>(portValue).
   e. If pos != end, return false (leftovers: a second colon, a trailing period, and so on).
   f. Write outAddress = address and outPort = port. Return true.

5. `bool extractIPv4(const std::string& str, unsigned long& outAddress, int& outPort)`
   a. Set the failure defaults (A21).
   b. i = 0. While i < str.size():
        - If str[i] is not a token character: i++ and continue.
        - Otherwise start = i; advance i while it is still a token character; end = i. (That is the maximal run from A7.)
        - Call parseCandidate(str, start, end, ...) using local temporaries. If it returns true, copy the temporaries into the output parameters and return true.
        - If it returns false, just keep looping; i already sits at the end of the failed token.
   c. After the loop, return false.

main: loop as described in A24-A32. It calls extractIPv4 exactly once per non-END line and formats the output itself (inline in main, no separate print helper).
